## Prior Review Disposition

The first review returned `request changes` at `e9ea3e0` with two blocking
findings. Both are fixed:

1. **`schema list` is not config-free.** Reproduced: with `--config` at a
   missing path, `schema list` exits 2 `invalid_config` while `machine
   manifest` and `introspect` exit 0. The CLI's effects metadata agrees —
   `schema list` declares `local_filesystem_read@configuration_dependent`, the
   other two do not. The blanket claim is gone; the section scopes config-free
   to rungs 1, 2, 4 and states rung 3's behavior.

2. **The no-`jq` pipeline could report an empty catalog as success.**
   Reproduced: `sort` exits 0 regardless of upstream failure, and compact JSON
   yields zero resources. Replaced with a real JSON parse.

All four non-blocking refinements were taken.

## Post-Approval Changes

Two commits landed after the downstream approval and are **not** covered by it:

- `d0ce774` — records that `--filter`/`--search` on `zia locations` never reach
  sublocations, returning `[]` with exit 0, which reads as "not found".
  Prompted by an observed agent failure.
- `bb3ac58` — two defects found in the builder's own text during a final pass:
  - the no-`jq` fallback opened with `set -o pipefail` in a block tagged `sh`;
    `dash` (`/bin/sh` on Debian/Ubuntu) rejects it with "Illegal option -o
    pipefail", so the fallback failed in exactly the constrained environments
    it exists for. Replaced with capture-then-parse, verified under `dash` for
    both success and failure.
  - the empty-mode note was correct but vague. All 781 fields with no
    `allowed_modes` are `classification: secret`; the text now says so.
