## Expected Delta

- Invalid non-numeric or non-positive IDs reach the machine boundary as a shared
  sentinel and become `invalid_resource_id`.
- The CLI returns exit 2 and a value-free error envelope with operation,
  product, and resource context.
- No authentication or network call occurs for the invalid ID.
- Missing IDs, record-not-found, unsupported resource, live access, cancellation,
  and deadline behavior remain unchanged.
- `machine.v1` manifest and JSON field shapes remain unchanged.

## Invariants Claimed

- The original invalid ID and backend text are not retained by `MachineError`.
- `MachineError.Unwrap` exposes only the shared sanitized sentinel.
- The unexported cause cannot appear in JSON.
- The existing `zscaler.ErrInvalidResourceID` name remains a true alias.
- Kind-based exit mapping works even after a machine error crosses a JSON
  transport and loses its Go cause.
- Contract docs, constants, machine fixture, CLI golden, and surface rationale
  agree and are drift-tested.
