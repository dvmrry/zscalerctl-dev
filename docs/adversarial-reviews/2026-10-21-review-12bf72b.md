# Builder Handoff

## Intent

fix: address the 12bf72b external review (sign-in, proxy, refs, goldens)

From the external review of `integration/2026-10-09` at `12bf72b`:

- **Sign-in error text is static.** `signInError.Error()` no longer carries
  the transport cause's text, which can name the host; the cause stays behind
  `Unwrap` for classification.
- **A OneAPI sign-in timeout is `deadline_exceeded`, reason `timeout`.** The
  sign-in transport wrapper makes net/http enforce `Client.Timeout` through
  `Request.Cancel` as well as a context deadline (`knownRoundTripperImpl` is
  false for any wrapper), and the transport races the two. When the cancel
  wins, a real `http.Transport` returns a plain "request canceled", which
  classified as `unknown`. `signInTimeout` wraps a sign-in failure at or past
  the request context's deadline with `context.DeadlineExceeded`. This was a
  known gap in the 2026-10-19 sign-in artifact.
- **`--timeout` bounds connect and TLS handshake.** `directTransport` cloned
  `http.DefaultTransport` (30 s dial, 10 s handshake), so a `--timeout` longer
  than those never covered a slow connect. Both limits are removed;
  `Client.Timeout` bounds them with the rest of the request.
- **`doctor`/`config status` name an ignored `HTTPS_PROXY`.** With
  `HTTPS_PROXY`/`https_proxy` set and neither `ZSCALERCTL_PROXY_URL` nor
  `ZSCALERCTL_PROXY_FROM_ENV`, the proxy status reads `direct (HTTPS_PROXY is
  set but not used; set ZSCALERCTL_PROXY_FROM_ENV=true to use it)`.
  `config.Proxy.EnvironmentProxySet` keeps only the presence bit.
- **`refs check` skips audit fields, declared per reference site.** Fields
  that record which account changed a record are declared with
  `ziaAuditRef`/`ztwAuditRef` (type `auditRefTargets`) in the reference
  tables: all 40 references to an `admin-users` resource, including
  `lastModUser`, `exclusions.lastModifiedUser`, `lastModifiedUserId` and the
  nested `instanceIdentifiers.modifiedBy`. On a live tenant 134 of 136
  `url-filtering-rules` misses were `lastModifiedBy` naming one id outside
  `admin-users`. They are listed under `not_checked` as `audit_field` (after
  the not-rendered check, so a mode-omitted field still reads
  `not_rendered_in_mode`) and their target is not read for them. `refs to` is
  unchanged. `FieldReferenceErrors` rejects an audit site that does not
  target `admin-users`; a test rejects an `admin-users` reference that is not
  declared audit.
- **`refs` logs progress** at `--log-level info` ("refs reading resource").
- **Golden version cases** build with `-buildvcs=false`; Go stamps a build
  from a main checkout (not a linked worktree), so they failed in a clone.

Not changed, with reasons:

- `TestSessionRetriesExhaustedMatchesTheRealSDKError` already drives the real
  SDK client (the external review lists it as open).
- A persistent 401 after refresh stays labelled `forbidden`: the SDK drops the
  status; both are non-retryable.
- `refIDKey` leading zeros: Zscaler ids are canonical integers; folding `007`
  into `7` could also make opaque string ids collide.
- `refs to` does not echo the queried id: it is an unvalidated argument and
  the document is `OutputSafe` (not re-scanned); the caller has it already.
