# zscalerctl v0.16.0

This release contains all changes since `v0.15.1`. Upgrade is recommended,
especially for operators using explicit legacy ZIA credentials.

## Security fixes

- Legacy ZIA authentication now refuses redirects. This prevents Go from
  replaying a credential-bearing authentication request to a redirect target
  after a `307` or `308` response. OneAPI authentication is unaffected.
- Legacy ZIA cloud validation now runs before `file:`, `keyring:`, or `cmd:`
  secret providers are resolved, so an unsupported destination cannot trigger
  credential materialization or operator-configured provider execution.
- Human resource and diff output visibly escapes terminal control and Unicode
  format characters after filtering and projection. JSON, NDJSON, dump data,
  and stdio wire values remain lossless.
- Dump replacement now validates complete artifact structure and collection
  state, stages the full replacement privately, and publishes at the directory
  boundary. `dump --force` no longer trusts a schema-prefix lookalike.

## Important compatibility change

Explicit legacy ZIA authentication now accepts only reviewed cloud names:

- `ZSCALER`
- `ZSCALERONE`
- `ZSCALERTWO`
- `ZSCALERTHREE`
- `ZSCLOUD`
- `ZSCALERBETA`
- `ZSCALERGOV`
- `ZSCALERTEN`
- `ZSPREVIEW`

Matching is case-insensitive and ignores surrounding whitespace. Any other
`ZSCALERCTL_ZIA_CLOUD` value now fails before secret providers or network
access with `missing_credentials` (exit `3`). If Zscaler has assigned your
tenant a legitimate legacy cloud outside this list, file an issue before
upgrading with the cloud name but no tenant identifier or credential material;
do not disable or work around the destination check. If continued `v0.15.1`
use is temporarily unavoidable, restrict it to a trusted network path and plan
the migration promptly because it lacks the redirect protection above.

## Engine and data-safety improvements

- The reusable Go engine now has a candidate stdio protocol and dependency-free
  TypeScript reference client for future local frontends. These remain
  candidate surfaces and do not change the supported CLI contract.
- Selective dump comparison distinguishes collected, failed, and unselected
  resources and rejects mismatched collection scopes instead of treating
  absence as an empty successful result.
- Dump manifests, redaction reports, error records, record counts, paths, and
  artifact inventories are reconciled before diff or destructive replacement.
- Missing product credentials retain exit `3`, configured request timeouts
  retain `deadline_exceeded`/exit `5`, and cancellation/publication boundaries
  no longer report cancellation after a dump has committed.
- On Windows, publishing a new dump destination remains supported; replacing
  an existing directory is intentionally unsupported and returns exit `4`
  because the required atomic directory exchange is unavailable.

## Resource completeness and coverage

- SSL inspection rules expose reviewed action metadata, including decrypt and
  do-not-decrypt sub-actions plus interception-certificate ID, name, and
  default-certificate status. Certificate contents and key material remain
  excluded.
- ZIA URL-category lists now include `TLD_CATEGORY` records.
- URL-filtering rules, location groups, and every production reader path that
  reached known unbounded ZIA, ZPA, ZTW, or ZCC SDK pagination now use bounded,
  fail-closed page walks without returning partial results.
- Location groups now include reviewed parent-location and sublocation
  membership in standard redaction mode.
- `ZPATWO` keeps its product API routing while OAuth uses
  `<vanity>.zslogin.net`; Zidentity admin reads use the reviewed admin host.

Eight low-cardinality ZIA endpoints remain explicitly deferred until live
evidence establishes their pagination contracts: admin roles, DC exclusions,
source and destination IP groups, NSS servers, sandbox rules, SSL inspection
rules, and time windows.

## Release integrity

- CI and release jobs now obtain Node from one committed `.node-version` pin.
  A YAML-aware gate requires both jobs to provision it before running the
  dependency-free TypeScript client tests and keeps package-manager caching
  disabled.
- Release archives continue to include per-target CycloneDX SBOMs,
  `SHA256SUMS`, keyless Sigstore signing, and GitHub provenance attestations.

The OpenTUI workspace remains an unsupported source-tree experiment and is not
part of the released `zscalerctl` binary.
