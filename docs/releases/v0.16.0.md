# zscalerctl v0.16.0

This release contains all changes since `v0.15.1`. Upgrade is recommended,
especially for operators using explicit legacy ZIA credentials.

## Important compatibility changes

### Introspection v2

The default `zscalerctl introspect` response changes from
`introspect_version: "1"` to `"2"` and uses the immutable
`introspect-v2.schema.json` URL. The released v1 schema and URL remain frozen.

Version 2 adds structured, condition-aware local-file, network, and process
effects for every command. The compatibility `mutating` boolean is now derived
conservatively and is `true` for every command because even tenant-read-only
commands can read local configuration, execute an operator-configured provider
or platform helper, contact Zscaler, or write through `--output`. Consumers
that need detail should evaluate `effects`, not infer behavior from `mutating`.
Consumers hard-coded to the v1 shape must branch on `introspect_version` before
upgrading.

### Legacy ZIA cloud allow-list

Explicit legacy ZIA authentication now accepts only reviewed cloud names:

- `ZSCALER`
- `ZSCALERONE`
- `ZSCALERTWO`
- `ZSCALERTHREE`
- `ZSCLOUD`
- `ZSCALERBETA`
- `ZSCALERGOV`
- `ZSCALERTEN`
- `ZSPREVIEW`

Matching is case-insensitive and ignores surrounding whitespace. Any other
`ZSCALERCTL_ZIA_CLOUD` value now fails before secret providers or network
access with `missing_credentials` (exit `3`). If Zscaler has assigned your
tenant a legitimate legacy cloud outside this list, file an issue before
upgrading with the cloud name but no tenant identifier or credential material;
do not disable or work around the destination check. If continued `v0.15.1`
use is temporarily unavoidable, restrict it to a trusted network path and plan
the migration promptly because it lacks the redirect protection below.

### Local filesystem trust boundaries

On macOS and Linux, a dump destination's immediate parent must now be owned by
the current user and must not be group- or world-writable. Writable ancestors
are accepted only when sticky-directory rules protect the next user-owned path
component; ancestors owned by another unprivileged principal are rejected. On
macOS, permit or unknown extended-ACL entries in that resolved ancestry are
also rejected. Operators writing below a shared or delegated directory may
need to choose an owner-controlled parent before upgrading.

On macOS, mode `0600` alone is no longer sufficient for a file-backed secret:
any extended ACL causes owner-only validation to fail closed. Remove the ACL or
copy the secret into an owner-only file without extended ACL entries before
using a `file:` provider.

## Security fixes

- Legacy ZIA authentication now refuses redirects. This prevents Go from
  replaying a credential-bearing authentication request to a redirect target
  after a `307` or `308` response. OneAPI authentication is unaffected.
- Runtime configuration resolves only credentials for the selected auth mode.
  Legacy ZIA cloud validation also runs before `file:`, `keyring:`, or `cmd:`
  providers, so an unsupported destination cannot trigger secret
  materialization or operator-configured provider execution.
- Structured redaction preserves valid JSON while scanning decoded and escaped
  rendered strings, including escaped high-entropy token forms; malformed or
  unreviewed structured values continue to fail closed.
- Human resource and diff output visibly escapes terminal control and Unicode
  format characters after filtering and projection. JSON, NDJSON, dump data,
  and stdio wire values remain lossless.
- Dump replacement now validates complete artifact structure and collection
  state, stages the full replacement privately, and publishes at the directory
  boundary. `dump --force` no longer trusts a schema-prefix lookalike.

## Automation-contract corrections

- Invalid numeric resource IDs now return `invalid_resource_id`, exit `2`,
  instead of looking like retryable live-access failures.
- Missing product-specific credentials such as
  `ZSCALERCTL_ZPA_CUSTOMER_ID` retain `missing_credentials`, exit `3`.
- Configured HTTP-client timeouts retain `deadline_exceeded`, exit `5`.
- Global `--output` help now states that it creates or replaces a local file
  and cannot be combined with `dump`.

## Engine and data-safety improvements

- The reusable Go engine now has typed read, catalog, status, URL lookup, dump,
  and diff operations plus a candidate stdio protocol and dependency-free
  TypeScript reference client for future local frontends. These remain
  candidate surfaces and do not change the supported CLI contract.
- Selective dump comparison distinguishes collected, failed, and unselected
  resources and rejects mismatched collection scopes instead of treating
  absence as an empty successful result.
- Dump manifests, redaction reports, error records, record counts, paths, and
  artifact inventories are reconciled before diff or destructive replacement.
- Cancellation/publication boundaries no longer report cancellation after a
  dump has committed, and confidential replacement cleanup cannot be killed by
  the stdio client's normal cancellation watchdog.
- Projection-copy and diff-memory reductions lower allocation and retained
  memory without changing rendered data.
- On Windows, publishing a new dump destination remains supported; replacing
  an existing directory is intentionally unsupported and returns exit `4`
  because the required atomic directory exchange is unavailable.

## Resource completeness and coverage

- SSL inspection rules expose reviewed action metadata, including decrypt and
  do-not-decrypt sub-actions plus interception-certificate ID, name, and
  default-certificate status. Certificate contents and key material remain
  excluded.
- ZIA URL-category lists now include `TLD_CATEGORY` records.
- URL-filtering rules, location groups, and every production reader path that
  reached known unbounded ZIA, ZPA, ZTW, or ZCC SDK pagination now use bounded,
  fail-closed page walks without returning partial results.
- Location groups now include reviewed parent-location and sublocation
  membership in standard redaction mode.
- `ZPATWO` keeps its product API routing while OAuth uses
  `<vanity>.zslogin.net`; Zidentity admin reads use the reviewed admin host.

Eight low-cardinality ZIA endpoints remain explicitly deferred until live
evidence establishes their pagination contracts: admin roles, DC exclusions,
source and destination IP groups, NSS servers, sandbox rules, SSL inspection
rules, and time windows.

## Release integrity

- Go `1.26.5` is enforced across modules and workflows as the security patch
  floor.
- CI and release jobs now obtain Node from one committed `.node-version` pin.
  A YAML-aware gate requires both jobs to provision it before running the
  dependency-free TypeScript client tests and keeps package-manager caching
  disabled.
- Secret scanning no longer contains the broad private-key allow-list pattern
  that could suppress a real key when a nearby marker string was present;
  regression fixtures exercise both working-tree and history policy.
- External actions remain full-SHA-pinned and workflow policy is parsed as
  YAML, preventing comments or duplicate/dynamic keys from spoofing pins.
- Release archives continue to include per-target CycloneDX SBOMs,
  `SHA256SUMS`, keyless Sigstore signing, and GitHub provenance attestations.

The OpenTUI workspace remains an unsupported source-tree experiment and is not
part of the released `zscalerctl` binary.
